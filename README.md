# ShadowPoll

A privacy-preserving Yes/No polling contract built with [Compact](https://docs.midnight.network/) for the Midnight network. This is a **New Moon** (Level 1) submission: toolchain set up, first contract written and compiled, deployed to a public testnet, with an initial product idea below.

## Product idea

ShadowPoll is a minimal building block for private governance on Midnight: anyone can publish a Yes/No question, and anyone holding a voter credential can cast exactly one ballot without ever revealing *who* they are or *which* choice they made being linkable back to their identity — only the running tallies and a set of spent "nullifiers" are public. The core mechanic (a private witness authenticates the caller, and only a one-way hash derived from it is disclosed) generalizes past simple polls to DAO governance votes, sealed-bid style community decisions, anonymous employee surveys, or whistleblower attestations — anywhere a group needs a verifiable, non-repeatable action from its members without a central party learning who did what.

## The contract

```compact
export ledger question: Opaque<"string">;
export ledger yesVotes: Counter;
export ledger noVotes: Counter;
export ledger nullifiers: Set<Bytes<32>>;

witness voterSecretKey(): Bytes<32>;

export circuit castVote(voteYes: Boolean): [] {
  const nullifier = disclose(voteNullifier(voterSecretKey()));
  assert(!nullifiers.member(nullifier), "This voter has already cast a ballot in this poll");
  nullifiers.insert(nullifier);
  const disclosedVote = disclose(voteYes);
  if (disclosedVote) { yesVotes.increment(1); } else { noVotes.increment(1); }
}
```

### Public ledger state vs. private witness

- **Public ledger state** (`question`, `yesVotes`, `noVotes`, `nullifiers`) lives on chain and is readable by anyone who queries the contract — that's the whole point of a public tally.
- **Private witness** (`voterSecretKey`) never leaves the voter's machine. It's supplied locally when building the zero-knowledge proof, and the compiler will not let it silently leak: reading it, or branching public ledger writes on a value derived from it, requires an explicit `disclose(...)` call. That's Compact making "what becomes public" an opt-in decision at every step, not a default.
- In `castVote`, we deliberately disclose two things and nothing else:
  1. `voteNullifier(voterSecretKey())` — a `persistentHash` of the secret key with a domain-separation tag. It's one-way, so nobody can recover the secret key from it, but it's deterministic, so the same voter always produces the same nullifier and a double vote is caught by `nullifiers.member(...)`.
  2. The boolean vote choice itself, `voteYes` — disclosed so it can move the public counters. (Compact treats *every* circuit argument as witness-like by default; even a plain boolean parameter needs `disclose()` before it can affect a branch that writes to the ledger.)
- What's never disclosed: the raw `voterSecretKey`, and any link between a specific nullifier and the real-world identity that produced it.

## Setup

Prerequisites: [Docker](https://www.docker.com/) running locally, Node.js 22+ (tested on Node 26), and the [Compact toolchain](https://docs.midnight.network/tutorial/creating/setting-up) (`compact` CLI + a downloaded compiler version via `compact update`).

```bash
npm install
```

### Compile the contract

```bash
cd contract
npm run compact   # runs: compact compile src/shadow_poll.compact ./src/managed/shadow_poll
```

This regenerates `contract/src/managed/shadow_poll/`, containing:
- `zkir/castVote.zkir` — the compiled ZK circuit
- `keys/castVote.prover` / `keys/castVote.verifier` — the proving and verifying keys
- `contract/index.js` / `.d.ts` — the TypeScript contract API
- `compiler/contract-info.json` — the circuit/ledger manifest

See `screenshots/compile-output.png`.

### Run the test suite

```bash
cd contract
npm test
```

Runs an offline simulator (`@midnight-ntwrk/compact-runtime`) against the compiled contract — no proof server, indexer, or wallet needed. See `screenshots/test-output.png`.

### Deploy to a testnet

Docker must be running. The proof server runs locally regardless of which remote network you target (only the indexer/node/faucet endpoints are remote); start it once and leave it running (first start downloads ~25MB of ZK parameters):

```bash
cd cli
npm run proof-server:up   # docker compose up -d — wait ~1-2 min for it to finish downloading
npm run deploy:preview   "Should ShadowPoll ship its New Moon milestone?"
# or
npm run deploy:preprod   "Should ShadowPoll ship its New Moon milestone?"
```

This will:
1. Generate a fresh wallet and print its address.
2. Request tDUST from the network faucet and wait for funds to arrive.
3. Register received NIGHT for dust generation (to pay transaction fees).
4. Submit the ShadowPoll deployment transaction and print the resulting **contract address**.

See `screenshots/deploy-output.png` for a completed run, and [Deployment](#deployment) below for the live address.

### Cast a vote

```bash
cd cli
node --loader ts-node/esm src/launcher/vote-preview.ts <contractAddress> yes <fundedWalletSeed>
```

## Live dashboard

A read-only dashboard reads the deployed contract's state straight from the public
Midnight Preview indexer (no mock data) and renders the live question, Yes/No tallies,
and nullifier count, plus a supplementary Three.js visualization of the privacy model
(a "private witness" flowing through a "privacy core" into a public nullifier and
ledger — decorative, `aria-hidden`, with a static/reduced-motion fallback; every
number it reflects is also plain accessible HTML on the same page).

```bash
cd web
npm run dev    # http://localhost:3000
```
